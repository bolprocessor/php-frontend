# Data projects (-da files)

A data project holds scores typed by hand or imported (MIDI, MusicXML). The interface (`php/data.php`) shows each **item** with its own PLAY button, and the same output formats as grammars.

## Layout

```
// Comments start with //
-se.robot_semaphore
-al.robot_semaphore
-so.robot_semaphore
-cs.Robot

// Comments may separate the items

[Hello world]
_tempo(2) H E L L O space W O R L D

[The traditional distress signal]
S O S space S O S
```

- First lines: the files the project needs, as in a grammar (files.md).
- **Items are paragraphs separated by blank lines.** An item may have several lines, e.g. a `[title]` on its own line above the score; the console plays the lines of an item one after the other and skips lines containing only a `[...]` comment. The lines of an item are joined into one (consoles compiled before 2026-11-27 played them as separate chunks), so a score may be wrapped on several lines, even within a polymetric expression; a line containing `,` or `.` outside braces is taken as one expression between braces. Don't leave a blank line inside an item. An error in any line stops the whole item: to keep independent examples apart, separate them by blank lines.
- A paragraph starting with `//` or `-`, or containing only a `[comment]`, is not an item.
- A bracketed comment at the start of an item is its title. Other `[...]` comments may be placed anywhere in the item: they are ignored.
- Csound score lines (`i1 ...`, `f1 ...`, `t ...`, `s`, `e`) placed in or after an item are a reference score for that item: they are removed before playing.
- `•` is read as ` .` and `…` as `_rest`.
- A line `-gr.NAME` in a data project names a grammar used to analyse its items (https://bolprocessor.org/parsing-items/). It is not played.
- Items are numbered from 1 in the interface.

## Data or grammar?

- A **data project** suits fixed pieces, collections of examples or variants to compare, and imported scores. Each item can be played alone.
- A **grammar** suits pieces generated by rules: variations, random choices, repetitions with transformations, structures built from smaller parts. A grammar can also be written to produce exactly one fixed piece in a structured way (`-gr.robot_objects`).
- Everything in a data item must be playable (notes, silences, terminals of the alphabet, controls): a word starting with an uppercase letter that is neither a note nor a terminal of the alphabet is read as a variable, and is silent (the alphabet of `-da.robot_semaphore` declares the letters `A`…`Z`, so they are terminals). Long structures repeated in a data project are a sign that a grammar would be clearer.

## Imported scores

MusicXML imports (`ctests/Imported_MusicXML/`) produce long items, one polymetric expression per measure with the measure number as a comment (`[—2—]`), `_tempo()`, `_vel()` and `_chan()` per part, and settings in their own `-se` file. Comments at the top of the file describe the import options. See https://bolprocessor.org/importing-musicxml/.
